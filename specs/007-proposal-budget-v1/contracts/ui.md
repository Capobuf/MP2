# UI Contract: Initial Proposal and Budget v1

All pages are inside the selected Company tenant and use Italian text. `visualizza`
permits reading Proposal/Budget data, `gestisce_proposte` permits Draft creation and
planning actions, and `approva_budget` permits approval. Direct URLs, selectors,
downloads and submissions remain scoped to the exact Company.

## Esercizio integration

The Exercise view shows Proposal/Budget status. For an Open Exercise without Budget,
an authorized manager sees `Inizializza proposta`. Confirmation explains that the
Proposal is isolated and that Actuals remain unchanged. Closed, foreign-company,
already-budgeted, or already-Draft Exercises show a precise disabled reason.

After success the user is taken to the Proposal view. Concurrent duplicate attempts
return the existing Draft only for an idempotent retry; otherwise they are rejected.

## Proposte Resource

Navigation label `Proposte`. The tenant list shows Exercise, purpose, state, Item
counts by readiness, total planned allocation, creator and last update. Terminal
rows have no mutation actions.

The Proposal view contains:

- identity, Exercise, purpose and state;
- `Realtà effettiva in sola lettura` summary;
- Item table with source type, live/new identity, lineage, archive indication,
  baseline/result allocation, Actual context, readiness and reasons;
- ordered typed actions and their reasons;
- readiness impact grouped by affected Exercise;
- Timeline link;
- source-specific planning actions;
- `Ricalcola verifiche` and `Approva e crea Budget v1`.

## Source-specific planning

The Expense flows support new planned Expense, canonical copy from a prior open
Exercise, Estimate plan replacement (including explicit annul/restore), supported
ownership/Supplier/Cost Center/lifecycle changes, and residual-plan repositioning as
a distinct new Expense. Inputs that would edit/move Actuals, create Contract manual
Estimates, or cross a closed Exercise are rejected with the canonical reason.

The Project flows support a new Planned Project, Estimate changes through planned
child Expenses, annual Cost Center when no Actual is reclassified, and supported
future state transitions. Riporto/Riprogrammazione controls are absent.

The Contract flows support a new Planned Contract, future condition/economic,
lifecycle, renewal/deadline and annual Cost Center decisions. The UI displays
requested/minimum/effective dates and `Prorata applicato: no`; a changed effective
date must be explicitly reconfirmed. Economically used Supplier change and manual
Contract Estimate are unavailable.

`Collega Progetto e Contratto` accepts live OriginKeys or same-Proposal Project and
Contract ProposalItemIDs. `Sostituisce` is not displayed or accepted.

Every successful planning command refreshes Item result/readiness and appends one
typed event. Input changes invalidate any displayed preview.

## Readiness review

`Ricalcola verifiche` displays:

- every affected Exercise and source;
- old/new allocation and state;
- Budget references that remain unchanged;
- other Drafts made stale, when applicable;
- warnings;
- closed-code blocks with an Italian domain explanation.

Statuses are exactly `Allineato`, `Da prendere in visione`, `Da riallineare`, and
`Incoerente`. S6 offers no `Ricarica realtà`, `Mantieni proposta`, or manual
realignment resolution; those controls are visibly assigned to S7.

## Approval

The Proposal view allows an authorized manager to upload a new private, versioned
evidence attachment to the Draft. The approval modal requires a stable operation
identity generated by the UI and asks for optional external subject/venue, optional
note, and optional eligible same-company Draft/live evidence attachments. It repeats
the final affected-Exercise impacts and states that the operation applies all plan
actions and creates immutable Budget v1.

Submission rechecks `approva_budget`, tenant, Proposal state, revisions, membership,
typed actions and all affected Exercises. On a stale or invalid result no effect is
shown as completed. A lost-response retry with the same identity opens the existing
Budget. Success redirects to Budget v1.

## Budget Resource

Navigation label `Budget`. It has list/view only. The list shows Exercise, `v1`,
purpose, approval time/author and total approved allocation.

The view materializes header, affected Exercises, approval evidence and every source
row. Drill-down shows Expense Estimate Lines, Project states/transitions/child
planning, or Contract conditions/cycles/deadlines/composition as applicable. It
never resolves current labels or hides archived live sources.

Actuals, operational variance, residual, saving, final overspend, late corrections,
Forecast and Closing fields are absent from Budget baseline UI. There are no edit,
delete, bulk delete, Revision, Closing, report/export or restore-as-live actions.

Evidence downloads authorize against the Budget Company and remain available after
the original live attachment is detached.

## Empty, error and accessibility behavior

Empty Item/evidence collections use explanatory Italian zero states. Readiness and
approval show progress and disable duplicate submission. Status is conveyed by text
and icon in addition to color. Actions have explicit labels and confirmation copy;
validation errors are associated with the relevant field. Standard Filament focus,
keyboard and responsive behavior is retained.
